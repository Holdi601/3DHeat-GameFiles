# Ενημερώσεις {#updates}

Το 3DHeat GameFiles ελέγχει τις κυκλοφορίες αυτού του αποθετηρίου στο GitHub όταν ξεκινά, λέει πότε υπάρχει νεότερη έκδοση και προσφέρει ενημέρωση. Τα δικά σας αρχεία (γύροι, εξαγωγές) δεν αγγίζονται ποτέ.

Πηγή: [`heat3d_update/__init__.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_update/__init__.py),
[`heat3d_update/__main__.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_update/__main__.py).
Η εγκατεστημένη έκδοση είναι το αρχείο [`VERSION`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/VERSION) του αποθετηρίου.

## Ο έλεγχος κατά την εκκίνηση {#the-check-at-start-up}

Κάθε εκτέλεση του `python -m heat3d_gamefiles ...` καλεί τον έλεγχο προτού διαβάσει τα ορίσματά της:

- Ρωτά το `https://api.github.com/repos/Holdi601/3DHeat-GameFiles/releases/latest`, με χρονικό όριο **5 δευτερολέπτων**.
- Η απάντηση αποθηκεύεται για **6 ώρες** στο `%LOCALAPPDATA%\3DHeat\update-check-3DHeat-GameFiles.json` (ή στο `~/.cache/3DHeat/...` χωρίς `LOCALAPPDATA`). Μέσα σε αυτό το διάστημα δεν γίνεται αίτημα. Το «δεν υπάρχει κυκλοφορία ακόμα» (HTTP 404) αποθηκεύεται κι αυτό.
- Εκτός σύνδεσης, με όριο αιτημάτων ή πίσω από διακομιστή μεσολάβησης, ο έλεγχος απλώς επιστρέφει και το εργαλείο τρέχει με την έκδοση που έχει.
- Αν η ετικέτα της τελευταίας κυκλοφορίας (`v1.2.3` ή `1.2.3`· ό,τι βρίσκεται μετά από `-` ή `+` αγνοείται) είναι νεότερη από το `VERSION`, τυπώνει στο stderr:

  ```
  [heat3d_gamefiles] 3DHeat GameFiles 1.1.0 is out (this is 1.0.1). https://github.com/...
  ```

- **Σε τερματικό** (stdin και stderr είναι και τα δύο TTY) ρωτά `Update now? [Y/n]`. Enter, `y`, `yes`, `j` ή `ja` κάνει την ενημέρωση. Μετά από επιτυχημένη ενημέρωση, **η ίδια εντολή ξεκινά ξανά** με τον νέο κώδικα, και ο κωδικός εξόδου της περνά.
- **Χωρίς τερματικό** (προγραμματισμένη εκτέλεση, σωλήνας) τυπώνει μόνο το μήνυμα ``Run `python -m heat3d_update` in <folder> to update.`` και συνεχίζει.

## Ενημέρωση κατά παραγγελία {#updating-on-request}

```
python -m heat3d_update          # update to the newest release, if there is one
python -m heat3d_update --check  # only say whether a newer release is out
```

Αυτό ρωτά πάντα το GitHub (χωρίς αποθηκευμένη απάντηση). Τυπώνει `Up to date: 1.0.1.`, `No release found (...)`, ή ό,τι έκανε. Ο κωδικός εξόδου είναι 1 αν η ενημέρωση δεν μπόρεσε να εφαρμοστεί.

## Πώς εφαρμόζεται μια ενημέρωση {#how-an-update-is-applied}

| Εγκατεστημένο ως | Ενημέρωση |
|---|---|
| ένα **κλωνοποιημένο git** (φάκελος `.git` και `git` στο PATH) | `git pull --ff-only`. **Απορρίπτεται** όσο τα ιχνηλατούμενα αρχεία έχουν τοπικές αλλαγές: "this checkout has local changes; commit or stash them, then run `git pull`". Τα μη ιχνηλατούμενα αρχεία δεν το εμποδίζουν |
| ένα **αντίγραφο λήψης** | το αρχείο πηγαίου κώδικα της κυκλοφορίας (`zipball_url`) κατεβαίνει και αποσυμπιέζεται σε προσωρινό φάκελο, αγνοώντας κάθε διαδρομή που θα έβγαινε έξω από αυτόν· το `VERSION` του πρέπει να είναι ίδιο με την έκδοση της κυκλοφορίας, αλλιώς δεν αντιγράφεται τίποτα· μετά τα αρχεία του αντιγράφονται πάνω σε αυτόν τον φάκελο |

Όταν αντιγράφει από το αρχείο, τα αρχεία που δεν ανήκουν στην κυκλοφορία (γύροι, εξαγωγές, εικονικά περιβάλλοντα, ό,τι φτιάξατε εσείς) μένουν ανέγγιχτα. Ο ενημερωτής προσπαθεί επίσης να διαγράψει τα αρχεία `.py` που μια κυκλοφορία αφαίρεσε από τα πακέτα της, ώστε μια παλιά ενότητα να μην σκιάζει την αντικαταστάτριά της. Ψάχνει πακέτα `heat3d_*` στη ρίζα του αρχείου και έναν φάκελο πιο κάτω, και αφαιρεί αρχεία `.py` που η κυκλοφορία δεν έχει πια.

## Απενεργοποίηση {#switching-it-off}

```
set HEAT3D_NO_UPDATE=1
```

Οποιαδήποτε τιμή εκτός από κενό, `0`, `false` ή `no` απενεργοποιεί και τον έλεγχο κατά την εκκίνηση και την προσφορά. Το `python -m heat3d_update` εξακολουθεί να λειτουργεί όταν τρέχει με το χέρι.
