# Source 2 `.vpk` {#source-2-vpk}

**Наведува и извлекува** VPK архиви на Valve, верзии 1 и 2, вклучувајќи поделени
архиви и податоци складирани во самата датотека на директориумот. Секој запис може да се провери
според својот CRC. Ова е единствениот формат на контејнер овде чиј производител го
документира. Игри: Counter-Strike 2, Dota 2, Half-Life: Alyx и други на Source 2.

Извор: [`vpk.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/vpk.py).
Команди: `identify`, `list`, `extract`.

## Распоред {#layout}

```
u32 magic 0x55AA1234, u32 version (1 or 2), u32 tree size
  (version 2: 16 more header bytes; header 12 or 28 bytes)
directory tree:
  extension        "vmdl_c", then "vtex_c", ..., then ""
    path           "maps/example_map", then ""
      file name    "world_layer0", then ""
        u32 crc, u16 preload size, u16 archive index, u32 offset, u32 length, u16 0xFFFF
        [preload bytes]
```

- Три вгнездени јамки, секоја завршува со празен низ, па читач што очекува
  број не наоѓа ниеден. Патеките се складирани еднаш по група и се составуваат од сите
  три дела. Едно празно место значи „нема папка“ или „нема наставка“.
- Секој запис завршува со `0xFFFF`. Тоа се проверува, па читач што го изгубил
  местото запира веднаш („директориумот не се чита на вистинското поместување“).
- **Поделени архиви:** `pak01_dir.vpk` го држи директориумот, а податоците се во
  `pak01_000.vpk`, `pak01_001.vpk`..., избрани според индексот на архивата на записот.
- **Индекс на архива `0x7FFF`** значи дека бајтите се во самата датотека на директориумот,
  по дрвото. Ако се чита како вистински индекс, читачот бара
  `pak01_32767.vpk`.
- **Preload:** малите датотеки се складирани цели во директориумот. Должина 0
  тогаш не е грешка.

## Команди {#commands}

```
python -m heat3d_gamefiles identify maps\example_map.vpk
python -m heat3d_gamefiles list maps\example_map.vpk --filter .nav
python -m heat3d_gamefiles extract maps\example_map.vpk maps/example_map.nav
```

`identify` ги печати верзијата, бројот на записи и првата датотека `.nav`. `list`
го прикажува секој запис како `stored`, бидејќи VPK не компресира. `extract` ги пишува
бајтите без проверка на CRC. Во Python, `VpkArchive(path).verify(name)`
ги споредува бајтите на записот со CRC што го забележал директориумот.

## Навигациската мрежа {#the-navigation-mesh}

Мапата испорачува своја **навигациска мрежа** (`maps/<map>.nav`) покрај компајлираната
геометрија. За топлинска мапа на позиции на играчи таа е многу покорисна од двете,
бидејќи навигациската мрежа *е* проодниот под, веќе пресметан и илјада пати помал.
Тестот со инсталирана игра проверува дека `.nav` на испорачана мапа почнува со магичниот број на Source navigation
`CE FA ED FE`.

## Проверено {#verified}

Секој запис земен како примерок низ испорачаните архиви на мапи на една игра излезе бајт по бајт точен
според својот CRC, и секоја архива на мапа се чита.
Тестовите со инсталирана игра ја повторуваат проверката на CRC на 25 случајни записи од секоја од
до четири архиви на мапи.

## Не е имплементирано {#not-implemented}

- Декодирање на компајлираните средства на Source 2 (`.vmdl_c`, `.vtex_c`). Тие се
  парчести бинарни датотеки од свој вид, ист вид работа како форматите на мрежи на Unreal и
  Frostbite. Одделната алатка 3DHeat CS2 ја обработува геометријата на мапите на CS2.
- Декодирање на навигациската мрежа на CS2. Нејзиниот формат е верзија 36 и се разликува од широко
  документираниот на Source 1. Нејзините бајти се структурирани, а не компресирани
  (ентропија 6,2, 31% нули), но само 3% од нејзините зборови се читаат како координати, па
  распоредот не е очигледниот и сè уште не е откриен.
