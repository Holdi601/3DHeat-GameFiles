# Unreal `.pak` {#unreal-pak}

**Исписује и извлачи** Unreal 4.22-5.x `.pak` архиве: верзије 8, 9, 10, 11 и 12, Zlib, Gzip и Oodle компресију, и шифроване архиве када дате AES кључ. Не тумачи оно што извуче (`.uasset`, `.umap`).

Извор: [`pak.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/pak.py).
Команде: `identify`, `list`, `extract` (видите [Команде](commands.md)).

## Распоред {#layout}

Подножје је на крају фајла и налази се претрагом последњих 1.024 бајта за магијом `0x5A6F12E1`. Редослед његових поља је важан:

```
[encryption key GUID : 16] [encrypted index : 1]
[magic : 4] [version : 4] [index offset : 8] [index size : 8]
[index SHA-1 : 20] [compression method names : 32 bytes each, up to 5]
```

Заставица шифровања стоји **пре** магије. Ако се узме иза магије, пада на „Z“ од „Zlib“. Тада се сваки архив пријављује као шифрован, а сваки назив метода губи прво слово („lib“, „odle“), тихо и правдоподобно. Верзија је најнижи бајт, јер градње са „замрзнутим индексом“ постављају један виши бит.

Индекс држи назив монтирања, индекс путања хеша, потпун индекс директоријума, и блок **кодираних уноса**: битовно спакован облик у коме заставица речи каже које бројеве су 32-битни, метод компресије (6 бита), да ли је унос шифрован, број блокова (16 бита) и величину блока у јединицама од 2.048 (6 бита). Величина блока у којој су сви битови 1 је *escape*: права величина следи као u32 **пре** офсета. У великој архиви, читање тога после померања величина погодило је 7% уноса за четири бајта и дало им офсете у ексабајтима.

Потпун запис сваког уноса понавља се непосредно пре његовог садржаја, па садржај почиње после `8+8+8+20+4+1+4` бајтова, плус `4 + 16 x blocks` кад је компресован. Шифровани блокови се поравнавају на 16 бајтова.

## Шта се чита, а шта одбија {#what-it-reads-and-what-it-refuses}

| Случај | Резултат |
|---|---|
| верзије 8-12 | чита се |
| било која друга верзија | `pak version N; this reader handles 8-12` (старије верзије чувају раван списак записа, а није било фајла за тест) |
| нема магије подножја | `has no pak footer. A UE 4.26+ title may ship its content as IoStore (.utoc/.ucas) instead` |
| индекс ван фајла | одбија се: подножје није парсирано онако како тврди |
| само индекс хеша путања | одбија се: називи фајлова су хеширани при градњи и не могу да се поврате |
| уноси у преливном списку индекса (директоријум офсет -1) | прескачу се, не измишљају се |
| шифрован индекс, без кључа | `EncryptedPak`: „Pass the AES key (`--key`, or `aes_key=` from Python) if you hold one; this tool does not recover keys.“ У командној линији, једна линија и излазни код 1 |
| шифрован унос, без кључа | `EncryptedPak` при читању |
| методи Zlib, Gzip, Oodle | распакују се (Oodle треба библиотеку, видите [Oodle](reader-oodle.md)) |
| било који други метод | `compression method '...' is not supported` |

## Кључеви {#keys}

`--key` уз `list` и `extract` узима AES-256 кључ који већ поседујете, као 64 хекса цифре, са или без `0x`. Све друго се одбија пре отварања архиве, са излазним кодом 2. Дешифровање је AES-256-ECB преко пакета `cryptography`. Не постоји путања кода која добија кључ: нема испоручених кључева, нема претраге извршних фајлова, нема читања меморије. Видите [Правила и лиценце](rules-and-licences.md).

## Проверено {#verified}

На испорученим архивама више игара, сваки унос, укључујући једну веома велику архиву, поклопио се са SHA-1 који Unreal пише пре сваког садржаја. Тај хеш покрива бајтове онако како су ускладиштени, па поклапање значи да су декодирање индекса, почетак садржаја и границе сваког компресованог блока били тачни. Тестови на инсталираним играма (`test_pak.py`) то понављају на до четири нешифрована pak-а нађена под `steamapps\common\*\...\Content\Paks`. Проверавају да сваки офсет уноса лежи унутар фајла и да SHA-1 важи за насумичан узорак од 150 уноса по архиви.
