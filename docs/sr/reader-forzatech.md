# ForzaTech: `.minizip`, `.modelbin`, узорци боја, постављања {#forzatech-minizip-modelbin-swatches-placements}

Forza Horizon ради на ForzaTech-у, сопственом мотору компаније Turn 10. Ови читачи узимају стазу из њених архива до позиционираних, текстурисаних троуглова. До њих се долази преко `course`, `courses` и `terrain` (видите [Forza Horizon](course-forza-horizon.md)). `identify` препознаје `.minizip` и самостални `.modelbin`, а `list` и `extract` узимају `.minizip`, по називима у `ChunkContentsMiniZip<n>.txt` поред њега или по броју уноса (`#12`).

| Формат | Модул |
|---|---|
| `.minizip` архиве и њихови списки имена | [`minizip.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/minizip.py) |
| `.modelbin` модели и терен | [`forzatech.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/forzatech.py) |
| `.pb` узорци боја | [`forzatexture.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/forzatexture.py) |
| `.pgeo` фајлови постављања | [`forzaplacement.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/forzaplacement.py) |
| `AssetManifest.xml` и хешеви текстура материјала | [`forzamaterial.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/forzamaterial.py) |
| плочице терена по месту | [`forzaterrain.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/forzaterrain.py) |

Forza такође већи део садржаја држи у обичним ZIP архивама под `media\`. Python-ов `zipfile` их отвара, а `forzatech.models_in_archive()` исписује њихове `.modelbin` уносе. Геометрија стазе је у `.minizip` архивама.

## `.minizip`: архива без имена {#minizip-an-archive-with-no-names}

Стаза испоручује четири `GeoChunk<n>.minizip` архиве, по десетине гигабајта за отворену мапу света, са стотинама хиљада уноса. **Архиве уопште не чувају називе**: нема табеле назива ни заглавља по уносу, само редни број. Називи су у `ChunkContentsMiniZip<n>.txt` поред сваке архиве, по један ред за сваки унос по редоследу уноса (`<build path>zipcache\pc\<path>|<bundle>`). То спаривање је једини начин да се затражи фајл. Све до `zipcache\pc\` се одбацује, а претраге не разликују велика и мала слова.

```
u32 'PGZP', u32 version (101), u32 header bytes (32), u32 entries,
u32 bundles, u32 entries per segment (512), u32 segments, u32 0
u32 bundle_start[bundles + 1]
padding to an 8-byte boundary
segments x:  u64 segment base (absolute), then (u32 offset, u32 size, u32 flags) x up to 512
```

Три детаља у индексу и даље дају излаз кад се погрешно читају. Читач их све три погађа:

| Детаљ | Шта погрешан читач ради | Како то изгледа |
|---|---|---|
| основа сегмента је **64-битна** | чита је као u32 плус поравнање | тачно за првих 4 GB, па шум исте дужине |
| основа је **поравната на 8 бајтова** | занемари поравнавајућу реч иза табеле пакета | у архивама са парним бројем пакета, сваки унос тврди кодек који не постоји |
| уписана дужина уноса је размак до следећег уноса (или основе следећег сегмента) **минус његово поравнање** (битови заставица 12-13) | узме цео размак | LZ4 одбија блок одмах |

Кодеци су најнижих пет бита заставица: `0x00` без компресије, `0x08` сирови deflate, `0x1F` LZ4 блок. Сваки други се одбија. Сваки унос се мора распаковати у тачно величину коју декларише, или се одбија. Индекс (око 5 MB) се чита једном, а садржаји се читају премотавањем.

Заглавље се проверава: магија, заглавље од 32 бајта, и број сегмената који се поклапа са `ceil(entries / per segment)`.

**Проверено:** узорковани уноси кроз сваку архиву мапе, сваки се распакује тачно у своју декларисану дужину под сва три кодека.

## `.modelbin`: контејнер блокова {#modelbin-the-chunk-container}

```
"burG" (the FourCC "Grub", little-endian), u32 version, u32 name-table offset, u32 file size, u32 chunk count
chunk count x 24 bytes: tag (reversed FourCC), flags, name offset, data offset, size, stored size
```

- Декларисана величина фајла мора бити једнака стварној величини.
- **Ланац**: сваки блок почиње тамо где се претходни завршио, заокружено на 4 бајта. Ништа у фајлу то не исказује, па је то доказ: запис прочитан погрешним кораком не даје то. Важило је за свих 252 узоркована модела.
- `PGZP` фајл дат читачу модела се назива „ForzaTech .minizip архива, не модел“ и упућује на `minizip.py`, уместо да се одбије нејасно.

Геометрију дају ови блокови:

| Блок | Садржи |
|---|---|
| `VLay` | распоред темена: називи атрибута, па елементи (u16 индекс назива, u16 канал, бафер, DXGI формат, офсет); број елемената је u16 |
| `VerB` | бафер темена иза заглавља од 16 бајтова (број, величина, u16 корак, u16 атрибути, формат) |
| `IndB` | бафер индекса, исто заглавље |
| `Mesh` | једна подмрежа: материјал, маска нивоа детаља, опсег индекса, распоред, бафер, корак, табела варијанти и кутија положаја на крају |
| `MatI` | инстанца материјала: њена `.materialbin` путања и хешеви текстура |

### Положаји и кутија {#positions-and-the-box}

Положаји су `R16G16B16A16_SNORM` (формат 13): четири потписана кратка броја по темену. `position = short / 32767 * scale + bias`, где су scale и bias последњих 32 бајта `Mesh` блока (два float4). Bias је у **светским координатама игре**, па плочица терена лежи тамо где је игра ставља без трансформације инстанце. Зато је довољан један круг телеметрије да затражи део мапе. Свака подмрежа модела носи исту кутију (проверено на 860 њих).

### Распоред темена {#the-vertex-layout}

Један бафер положаја покрива сва темена. Остали атрибути су подељени у узастопне групе темена, свака са својим баферима и својим распоредом: пут близу раскрснице има три UV групе и две тангенте, док обала поред њега има само нормалу. Сваки атрибут који није положај има четири бајта. Који распоред описује који бафер узима се из подмрежа које црпе из тог бафера, јер распореди и бафери нису у истом редоследу (исти, померен за један, или пермутован, зависно од модела).

| DXGI формат | Код | За шта се користи |
|---|---|---|
| R16G16B16A16_SNORM | 13 | положај (четврти кратки број је x нормале) |
| R16G16_SNORM | 37 | нормала y, z |
| R16G16_UNORM | 35 | пар UV-ова (канал = који скуп) |
| R8G8B8A8_UNORM | 28 | боја или тежине мешања |
| R10G10B10A2_UNORM | 24 | тангента (није декодирано) |
| R16_UINT | 57 | индекси |

**Нормала је подељена.** `NORMAL` држи y и z. x је четврти кратки број положаја, који је изгледао као поравнање. Преко стотина хиљада темена терена корелира са +0,92 са x нормале троугла и ни са чим другим. Уз њега, 96% темена на нагнутом тлу је у границама од 18° од израчунате нормале. Свако кодирање са две компоненте, испробана без тога (октахедрална у свих 48 распореда међу њима), давала су y и z исправно, а x погрешно.

Остали формати положаја или индекса се **одбијају** („only 13 (four shorts, scaled) is implemented“; „only unsigned shorts are implemented“).

### Подмреже {#submeshes}

Запис `Mesh` је 238 бајтова у стандардном облику. Дужи носе дужу табелу материјалних **варијанти** на почетку, 238 + 8 x count - 4 бајта, и свако поље иза ње се помери назад за тачно толико. Краћи (218 бајтова, нешто терена) задржавају офсете. Сваки унос варијанте је `u16 0xFFFF, u16 summer material, u16 0xFFFF, u16 winter material`. Маска нивоа детаља је u16, по један бит за сваки ниво почевши од бита 1.

Ништа се не узима само по себи. Опсези индекса морају тачно да покривају бафер индекса, сваки `index count` мора бити 3 x `triangles`, а корак који подмрежа наводи мора бити корак њеног бафера. Табела која не прође одбија се у целини, јер је боље не означити троуглове него означити их из погрешно прочитаних поља. Преко хиљада узоркованих подмрежа, свака чији је индекс бафера у опсегу прелази проверу.

### Материјали и хешеви текстура {#materials-and-texture-hashes}

`MatI` именује свој материјал путањом `Game:...\x.materialbin`, пронађеном претрагом блока. Његове текстуре су записи `u32 slot, u32, u32 hash`, на 33 бајта један од другог и без поравнања, па се блок претражује на сваком бајтовском офсету за речи које су познати хешеви текстура. Они долазе из `AssetManifest.xml` стазе (`<Texture Source="...\name.swatch" SourceHash="...">`, читано до `</Textures>`). Слот `0x88B483AA` је основна боја стандардног шејдера. Како се тада бира текстура боје, описано је у [Forza Horizon](course-forza-horizon.md#which-texture).

## `.pb`: узорци боја {#pb-texture-swatches}

Узорак је исти `burG` контејнер као модел: заглавље `HCXT` од 96 бајтова на бајту 44, па један блок пиксела. Заглавље држи GUID текстуре (онај из назива фајла), ширину и висину, број мипова и **код формата на бајту 72** (ForzaTech-ова властита нумерација). Бајт 84 држи број бајтова пиксела.

| Код | Формат | Препознато као |
|---|---|---|
| 0 | BC1, пола бајта по пикселу | декодује се у црвено-бели ивичњак (шум под BC4) |
| 9 | BC7, један бајт по пикселу | декодује се у плочицу терена на којој се види стаза |
| 13 | RGBA8, четири бајта по пикселу | обично |
| остало | одбија се | „texture format N has not been identified; refusing to guess“ |

Формати су препознати декодирањем правих фајлова на сваки начин који величина корисног садржаја дозвољава. Бајт 47, који је раније узет за формат, у свакој узоркованој текстури је 4. Декодира се само највећи мип фајла. Свака резолуција је свој унос, `<name>_<guid>_quality<n>.pb`, квалитет 1 најмањи до 5 највећи. За мапе терена два највећа су у другој архиви него остали. Декодирање иде кроз Pillow-ов BCn декодер, преко генерисаног DDS заглавља.

## Фајлови постављања (.pgeo) {#placement-files-pgeo}

Један фајл по категорији по просторној ћелији: `scene\proc\cellsize\<size>\<x>_<z>\c<size>_<category>_....pgeo`. Сама путања даје квадрат ћелије и категорију, па се фајлови могу филтрирати без отварања.

```
u32 length, name                 cell and section, for humans
u32 0, u32 13, u32 15
f32 x 8                          box: min xyz, pad, max xyz, pad
u32 length, CATEGORY
... a table of variant names (bare names) ...
per model:
  u32 length, <model name>_3D
  u32 count (1..200,000)
  count x 80 bytes:
    0-11   position: 3 x sign-magnitude 16.16 fixed point
    12-23  the model's x axis in the world (3 x f32)
    24-35  its y axis (3 x f32); z = x cross y
    36-47  scale (3 x f32)
    48-59  unknown
    60-63  material variant (u32)
    64-79  not needed to place it
```

Како је свако поље одлучено:

| Поље | Одлучено по |
|---|---|
| положај је 16.16 фиксна тачка, а не део кутије | узастопне заштитне ограде су тачно 4,000 m један од другог (дужина модела) |
| знак-величина, а не допуна до два | допуна до два је негативне координате вратила десетинама километара од мапе; са битом 31 као знаком, сваки запис сваке категорије узоркован је падао унутар кутије свог фајла |
| вектори су властите осе модела | крај сваке заштитне ограде лежи на почетку следеће: 93,5% у границама од 5 cm, медијана 0,000 m |
| бајт 60 је варијанта | пет копија једног билборда чита 0, 2, 2, 3, 4, док свака заштитна ограда чита 0 |

Само називи који се завршавају на `_3D` су записи модела. Табела варијанти пре њих наводи називе без тог суфикса, и ако се читају као записи, ти падају у бесконачност. Кандидат-запис се прихвата само ако његов број уклапа у фајл, а инстанце са не-коначним бројевима се бришу.

## Није реализовано {#not-implemented}

- Формати темена и индекса осим горњих (одбијају се).
- Формати текстура осим 0, 9, 13 (одбијају се).
- Тангенте (прескачу се, не користе се).
- Слојеви материјала шејдера терена. Текстура тла је тумачење мапа плочица (видите [Forza Horizon](course-forza-horizon.md#the-ground-texture)).
