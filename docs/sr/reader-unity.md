# Unity: `SerializedFile`, пакети, мреже {#unity-serializedfile-bundles-meshes}

**Исписује објекте и декодира мреже** Unity `SerializedFile` формата 22 и новијег (Unity 2020 до 6000), и отвара `UnityFS` пакете. Нема Unity извоза стазе.

Извори: [`unity.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/unity.py),
[`unity_mesh.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/heat3d_gamefiles/unity_mesh.py).
Команде: `identify` (контејнери и пакети), `meshes` (само голи контејнери).

## Контејнер {#the-container}

Unity испоручује ниво као серијализоване графове објеката: `globalgamemanagers`, `sharedassets*.assets`, `resources.assets`, `level*`, и пакете средстава. Сваки држи табелу објеката означених ID-јем класе.

Заглавље је место где читање тихо греши. Прва шеснаест бајтова су четири `uint32` у big-endian-у, која се држе ради компатибилности. У формату 22 три су нула, а стварне вредности следе, јер фајл може бити већи од 4 GB:

```
[legacy metadata size : 4] [legacy file size : 4] [format version : 4] [legacy data offset : 4]
[endianness : 1] [reserved : 3]
[metadata size : 4] [file size : 8] [data offset : 8] [unknown : 8]
```

Други `metadata size` је `uint32` између два `int64`. Ако се сва три узму као 64-битна, низ верзије помери се за четири бајта. Ипак се декодира као нешто што личи на низ, и све иза њега оде криво. Заглавље је big-endian. Све после њега прати бајт редоследа (0, little-endian, на сваком desktop-у).

Иза заглавља: низ верзије мотора, платформа, ознака табеле типова, табела типова (ID класе по типу), табела објеката (ID путање, офсет, величина, тип), и спољни фајлови на које показивач може да упућује.

| Случај | Резултат |
|---|---|
| формат 22-30 | чита се |
| формат 9-21 (пре Unity 2020) | одбија се: офсети су у старом заглављу, а ниједан фајл на руци га није користио |
| ван 9-30 | одбија се |
| уграђено стабло типова (уређивачке верзије) | одбија се: испоручене верзије га не уграђују, а уређивачка путања није реализована |
| пакет дат тамо где се очекује контејнер | одбија се, уз упут на читач пакета |

Опште **нема десеријализатора**. Испоручене верзије не носе стабло типова, јер је шема компајлирана у играч, па се свака класа парсира према распореду познатом за своју верзију. Декодира се само `Mesh`. Остале класе се пријављују по називу и броју (`GameObject`, `Transform`, `MeshRenderer`, `MeshFilter`, `Mesh`, `BoxCollider`, `MeshCollider`, `MonoBehaviour`, `MonoScript`, `AssetBundle`, `RectTransform`, `PrefabInstance`; остале као `class<id>`).

**Проверено** на многим инсталираним играма и милионима објеката: табела објеката мора тачно да покрива секцију података, без преклапања, ништа осим поравнања између објеката, а последњи објекат завршава на последњем бајту фајла. Погрешно читање заглавља то не може да произведе. Тест на инсталираној игри то понавља на до шест `resources.assets` / `sharedassets0.assets` фајлова у `*_Data` фасциклама.

## Пакети (`UnityFS`) {#bundles-unityfs}

Пакет је компресован контејнер SerializedFile-ова. Листа блокова и директоријум су такође компресовани. Метод је у најнижих шест бита флег речи: 0 без компресије, 1 LZMA (Unity-јево 5-бајтно заглавље са уметнутом величином), 2 и 3 LZ4 / LZ4HC. Формат 7 и новији поравнавају заглавље на 16 бајтова. Флег `0x80` ставља директоријум на крај фајла. `UnityWeb`, `UnityRaw` и `UnityArchive` (пре 5.3) се препознају али се не читају.

## Мреже {#meshes}

`read_mesh` декодира `Mesh` објекат у положаје, нормале, први UV скуп и троуглове, оним редом којим Unity 2019+ пише: назив, подмреже, облици мешања (прескачу се), бинд позе и подаци о костима (прескачу се), заставице компресије и читљивости, бафер индекса, канали темена и подаци темена, блок компресоване мреже, локална граница и подаци о стримовању.

- **Спољна темена.** Већина испоручене геометрије живи у `.resS` фајлу поред контејнера. Читач га чита из фасцикле контејнера (користи се само назив фајла из сачуване путање `archive:/...`). Недостајући `.resS` је грешка, а не празна мрежа.
- **Токови и канали.** Канали кажу који ток, офсет, формат и димензију има сваки атрибут. Токови су спаковани један за другим, сваки заокружен на 16 бајтова, па се почетак тока израчунава из корака пре њега. Формати: float32, float16, unorm/snorm 8 и 16 (нормализовани), и обични цели бројеви.
- **Топологија.** Само троуглови (топологија 0). Стрипови, четвороуглови и линије се одбијају, јер погрешна конверзија изгледа као права геометрија.
- **Компресоване мреже** (квантизоване разлике) се одбијају: „mesh '...' is stored compressed; that encoding is not implemented“.

### Самопровера {#the-self-check}

Читање структуре погрешним редом не подиже грешку. Даје правдоподобне бројеве. Зато се свака декодирана мрежа проверава према **граничној кутији коју је Unity сачувао за њу**, коју је уређивач израчунао из правих темена. `aabb_matches()` прође кад се углови декодиране кутије налазе у границама од 2% величине сачуване кутије. `meshes` исписује `ok` или `BOUNDS DISAGREE` на сваком реду.

**Проверено:** узорковане мреже кроз неколико игара декодирају се са слагањем граница. Тест на инсталираној игри понавља проверу на инсталираним контејнерима.

## Није реализовано {#not-implemented}

- Формати пре 2020.
- Компресоване мреже.
- Било која класа осим `Mesh`: нема графа сцене, трансформација или материјала, па су мреже у свом локалном простору.
- `meshes` на пакету. Читач пакета постоји у Python-у (`UnityBundle.serialized_files()`), али команда узима голи контејнер.
