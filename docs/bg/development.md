# Разработка {#development}

## Структура {#layout}

```
heat3d_gamefiles/     пакетът: четците, експортите на трасета, командният ред
heat3d_update/        проверката за нова версия и обновяването (вижте Обновления)
tests/                синтетични тестове, фикстури и тестове срещу инсталирани игри
docs/                 тази документация (docs/wiki се генерира от нея)
VERSION               инсталираната версия, сравнявана с издаванията в GitHub
requirements.txt      numpy, cryptography, lz4, Pillow, msgpack, zstandard, pytest
```

## Пускане на тестовете {#running-the-tests}

```
pip install -r requirements.txt
python -m pytest
```

`pytest.ini` задава `testpaths = tests` и `-q`. Два вида тестове имат значение, по различни причини:

- **Синтетичните тестове** строят архиви байт по байт и се пускат навсякъде. Фиксират оформленията на полетата, които някога са били грешни: 64-битовата основа на сегмента в `.minizip` и подравнителното запълване, екранирането на размера на блока в pak, u32 между два int64 в заглавката на Unity, индекса `0x7FFF` на VPK, разделения x на нормалата в Forza.
- **Тестовете с инсталирани игри** работят срещу истинските файлове, когато играта е на машината, и се **пропускат** (не се провалят), когато я няма. Те са единственото, което хваща оформление, което е вярно за малък файл и грешно за голям.

## Тестове с инсталирани игри {#installed-game-tests}

[`tests/installed.py`](https://github.com/Holdi601/3DHeat-GameFiles/blob/main/tests/installed.py)
намира игри за тестовете. `steam_common()` изброява `steamapps\common` на всяка библиотека на Steam (включително папките на самия Steam), а `installed(*globs)` връща пътищата, които съвпадат с някой от шаблоните под тях, рекурсивно, където шаблонът има `**`. Всеки тест решава какво му трябва:

| Тест | Търси | Пропуска се с |
|---|---|---|
| `test_pak.py` | `*/(*/){0..3}Content/Paks/*.pak` с **некриптиран** индекс, до 4 | „no shipped pak on this machine“ |
| `test_unity.py` | `resources.assets` / `sharedassets0.assets` в `*/*_Data` или `*/*/*_Data`, които четецът приема, до 6 | „no Unity game on this machine“ |
| `test_frostbite.py` | `Battlefield*/**/*.toc` | „no Frostbite game on this machine“ |
| `test_frostbitelevel.py` | `Battlefield*/**/levels/**/*.toc` | „no Frostbite level on this machine“ |
| `test_vpk.py` | `Counter-Strike Global Offensive/game/csgo/maps/*.vpk`, до 6 | „Counter-Strike 2 is not installed“ |
| `test_forzatech.py` | `ForzaHorizon*/media/*.zip` | „no Forza install on this machine“ |
| `test_forzaplacement.py` | трасетата от библиотеката с обиколки на FH Companion (старт и финал в рамките на 50 м), с най-много обиколки, които `find_track` намира; или `HEAT3D_COURSE` | „no Forza install with a recorded lap library here“ |
| `test_beamng.py` | `find_install()` | „BeamNG.drive is not installed“ |
| `test_acrally.py` | `find_paks()` | „Assetto Corsa Rally is not installed“ |

Пускане само на тестовете на една игра или насочване на теста за бордюри на Forza към трасе:

```
python -m pytest tests/test_vpk.py
set HEAT3D_COURSE=%LOCALAPPDATA%\FHCompanion\laps\Example Circuit (course_0_0_to_0_0)
python -m pytest tests/test_forzaplacement.py -k kerbs
```

Тестовете с инсталирани игри четат само от игрите. Нищо не записват в папките на игрите. Изходите на тестовете отиват в временните папки на pytest.

## Конвенции {#conventions}

- **Отказ вместо налучкване.** Всеки четец хвърля собствено изключение (`UnsupportedPak`, `IoStoreError`, `UnsupportedForza`, `UnsupportedUnity`, `UnsupportedFrostbite`, `UnsupportedVpk`, `BeamNGError`, `PropertyError`...) със съобщение, което казва какво е намерено и защо не е прочетено.
- **Проверка срещу самия формат.** Хеш, CRC, верига от отмествания, записана габаритна кутия, шофирането лежи на земята. Не „не се е сринал“.
- **Без ключове и без собствен код в пакета.** Вижте [Правила и лицензи](rules-and-licences.md).
- **Поверителните данни остават вън.** Файлове на игри, експорти, обиколки, записи и екранни снимки никога не влизат в хранилището. `.gitignore` ги изключва по папка и по вид. Тестовете ползват синтетични данни и инсталирани игри, никога съдържание на игри, качено в хранилището.
